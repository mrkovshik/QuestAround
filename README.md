# questaround

Движок городских игр: квесты, фото-охота, квесты-прогулки (позже онлайн-квизы).
Спецификация лежит в проекте «велоигры в Нови Саде»: `архитектура-платформы.md`,
`спецификация-сценарий-и-api.md`, `регистрация-команд.md`.

## Быстрый старт

```sh
go mod tidy                 # обновить go.sum
make test                   # без Postgres
docker compose up -d && make test-pg   # с Postgres

# фронтенд игрока (нужен Node 20+), вшивается в бинарник
make web

# сервер (без QUESTAROUND_DATABASE_URL — всё в памяти)
QUESTAROUND_ADMIN_TOKEN=$(openssl rand -hex 16) \
QUESTAROUND_DATABASE_URL=postgres://postgres:postgres@localhost:5432/questaround \
go run ./cmd/questaround serve
go run ./cmd/questaround validate internal/scenario/testdata/pilot.yaml
go run ./cmd/questaround routes -teams 5 internal/scenario/testdata/pilot.yaml
```

## Структура

```
cmd/questaround/            CLI: serve (HTTP-сервер), validate, routes
internal/
  scenario/               YAML-сценарий: типы, дефолты, валидация с номерами строк
    testdata/pilot.yaml   пример сценария (гибрид, пилот в Горячем Ключе)
  routes/                 маршруты команд: same | rotate | random | explicit, pin, chain
  core/                   движок Run: события, команды, flow, проверка ответов, лидерборд
  store/                  журнал событий + сценарии и игры: Memory и Postgres (миграции встроены)
  runner/                 актор игры: команды → журнал → подписчики, таймеры по NextDeadline
  httpapi/                HTTP API игрока и ведущего, SSE, загрузка фото
  webui/                  раздача собранного фронтенда (embed), SPA-маршруты
  telegram/               (todo) бот — второй транспорт
web/                      PWA игрока: Svelte 5 + Vite + TypeScript
  src/admin/              админка ведущего (отдельный чанк, игрокам не грузится)
  e2e/player_flow.py      прогон игры игрока в headless Chrome (playwright)
  e2e/host_flow.py        прогон админки вместе с игроком
```

## Что уже есть

**scenario**
- Строгий парсинг: опечатка в ключе — ошибка (`KnownFields`).
- Все ошибки за один проход, с номером строки и путём: `строка 12: levels[1].answers[0].pattern: …`.
- Значения по умолчанию: team 1–5, hint_requests: captain, start: simultaneous,
  flow: linear + routes: same, scoring: points, leaderboard: always,
  answer_normalize: trim, lower, yo_to_e.
- Автоподсказки без `after` получают время из `defaults.hint_after` по порядку.
- Проверки: id, типы ответов и лишние поля в них, regex компилируется, координаты,
  require, подсказки и штрафы, бонусы, pin/chain, explicit-маршруты, граф unlock
  (ссылки, циклы, стартовый уровень), staggered без interval, заморозка лидерборда.

**routes**
- `rotate`: команды равномерно разнесены по кругу (`offset = i·n/teams`);
  если команд больше, чем подвижных блоков, стартовые точки повторяются равномерно.
- `random`: детерминирован по `seed` и номеру команды (seed хранить в Run).
- Цепочки (`chain`) двигаются одним блоком, `pin: first/last` на месте.
- `Validate` проверяет любой маршрут; тест гоняет все режимы на 1–12 команд.

## Отличия от спецификации v0

- `defaults.hints` → `defaults.hint_after: [15m, 30m]` — расписание для подсказок
  уровня без явного `after` (текст подсказки всегда задаётся в уровне).
- `participants.hint_requests: captain | anyone` — кто берёт штрафные подсказки.
- `choice.correct` — значение из `options` (не индекс).
- `timing.mode: sync` пока отклоняется валидатором.

**core**
- `Game.Handle(now, cmd)` → события или ошибка без изменений состояния; `Replay(events)` → то же состояние.
- Команды: RegisterTeam, StartRun, StartTeam, SubmitAnswer, RequestHint, Moderate,
  Override, SetLeaderboard, SendBroadcast, FinishRun, Tick.
- Flow linear (маршруты из `routes`), storm, graph (all_of / any_of / count+of).
- Ответы: код/regex/choice с нормализацией, гео (радиус + порог точности → `inaccurate`),
  фото/текст → очередь модерации. Секторы (`require`), бонусы, повторы (`duplicate`),
  идемпотентность по `client_event_id`, rate limit на неверные коды.
- Подсказки по таймеру и по запросу (штраф временем/баллами, только капитан — по настройке).
- Старт simultaneous / staggered / manual, лимит времени от старта команды.
- Лидерборд: time / points / mixed, общие места при равенстве, видимость
  (сценарий + переключатель ведущего), заморозка со снимком.
- `NextDeadline()` — когда актору прислать Tick.
- Тесты: после каждого теста журнал переигрывается (напрямую и через JSON) и сверяется с состоянием.

## Решения, принятые в core

- Ответ кодом без `LevelID` ищется по всем открытым уровням (для storm/graph);
  порядок: незасчитанные ответы → бонусы → проверка на повтор.
- Бонусы можно сдавать и на пройденном уровне, пока команда в игре.
- Время команды обрезается лимитом, даже если Tick пришёл с опозданием.
- Заморозка лидерборда считается от конца лимита последней стартовавшей команды.
- В режиме `time` бонусы не уменьшают время (бонусы — только баллы).

**store**
- `EventStore`: `Append` атомарно и только продолжением журнала (иначе `ErrConflict`), `Load`.
- Версии сценариев (неизменяемые, номер растёт), игры с коротким `PublicCode` и `Seed`.
- Postgres: pgx, миграции из `migrations/*.sql` под advisory lock; Memory хранит события
  в JSON, как Postgres. Общий набор контрактных тестов гоняется на обеих реализациях.

**runner**
- Одна горутина на игру владеет `core.Game`; `Do(cmd)` отвечает только после записи в журнал.
- Сбой записи → состояние перечитывается из журнала, клиент получает ошибку.
- Таймер ставится на `NextDeadline()` — старты по расписанию, автоподсказки и лимит
  срабатывают сами, в том числе после рестарта.
- `Subscribe(teamID)` — канал «состояние изменилось» (последний seq, схлопывание) для SSE;
  пустой teamID — все изменения (ведущий).
- `Read(fn)` — чтение состояния внутри актора, без блокировок.
- Время округляется до микросекунд — состояние в памяти и после рестарта из Postgres совпадает.
- `Manager` поднимает акторы по требованию из хранилища.

**Регистрация (в core)**
- Капитан создаёт команду по публичному коду игры и получает инвайт; игроки вступают по инвайту
  (до старта и во время игры), первый вступивший в команду ведущего становится капитаном.
- Капитан: переименовать, удалить игрока, передать капитанство, перевыпустить инвайт, снять команду (до старта).
- Ведущий: открыть/закрыть регистрацию, лимит команд (ведущему лимит не мешает), команды вручную.
- Снявшиеся команды не стартуют и не попадают в таблицу.

**httpapi**
- Токен игрока `<runID>.<playerID>.<secret>`, в журнале только `sha256(secret)`;
  удалённый игрок теряет доступ сразу. Ведущий — статический `QUESTAROUND_ADMIN_TOKEN`.
- Ошибки: `{"error": "<код>", "message": "<по-русски>"}`; невалидный сценарий → 422 со строками.
- Игроку никогда не отдаются коды, регэкспы и координаты.
- SSE (`/api/v1/stream`, `/admin/v1/runs/{id}/stream`): `event: state_changed`, `data: <seq>`;
  токен можно передать `?token=` (EventSource не умеет заголовки).
- Фото: multipart `photo` + `level_id` / `bonus_id` / `answer_idx`; JPEG, PNG, WebP, GIF до 15 МБ;
  хранятся на диске (`QUESTAROUND_MEDIA_DIR`), отдаются только ведущему.

### API игрока

| | |
|---|---|
| `GET /api/v1/games/{code}` | инфо об игре, открыта ли регистрация |
| `POST /api/v1/games/{code}/teams` | `{team_name, captain_name, contact}` → токен капитана + инвайт |
| `POST /api/v1/games/{code}/join` | `{invite_code, name}` → токен |
| `GET /api/v1/state` | всё для экрана игрока |
| `POST /api/v1/answers` | `{kind: code\|geo\|text, value, lat, lng, accuracy, level_id, bonus_id, answer_idx, client_event_id}` |
| `POST /api/v1/photos` | multipart |
| `POST /api/v1/levels/{id}/hints/{idx}` | подсказка по запросу |
| `GET /api/v1/leaderboard` | 403 `leaderboard_hidden`, если скрыта |
| `GET /api/v1/stream` | SSE |
| `GET/PATCH /api/v1/team`, `DELETE /api/v1/team/players/{id}`, `POST /api/v1/team/{invite/rotate,captain,withdraw}` | команда |

### API ведущего (`/admin/v1`)

`POST /scenarios` (тело — YAML), `GET /scenarios/{id}`, `POST/GET /runs`, `GET /runs/{id}`,
`PUT /runs/{id}/registration`, `POST /runs/{id}/teams`, `PATCH /runs/{id}/teams/{tid}`,
`POST /runs/{id}/teams/{tid}/{start,withdraw,override,answers}`, `POST /runs/{id}/{start,finish,broadcast}`,
`GET /runs/{id}/{dashboard,stream,moderation,events}`, `POST /runs/{id}/moderation/{seq}`,
`PUT /runs/{id}/leaderboard`, `GET /media/{key}`.

**PWA игрока** (`web/`, ~40 КБ gzip)
- `/` — ввод кода игры; `/g/КОД` — регистрация или игра; `/g/КОД/join/ИНВАЙТ` — вступление по ссылке.
- Лобби: состав, ссылка-приглашение (поделиться / QR), действия капитана, обратный отсчёт до старта.
- Игра: задание, общее поле кода (ищет по всем открытым уровням и бонусам), секторы, варианты ответа,
  «Я на месте» (гео), фото с камеры (сжатие до 1600px JPEG), подсказки с таймером и штрафом,
  бонусы, сообщения ведущего, таблица (если открыта), финиш.
- Обновления по SSE + опрос раз в 30 с на случай, если прокси режет стрим.
- Офлайн: оболочка из service worker, ответы и фото копятся в IndexedDB и уходят сами
  (сервер дедуплицирует по `client_event_id`).
- Светлая и тёмная тема по системной настройке.
- Разработка: `make web-dev` (Vite на :5173 проксирует API на :8080).

**Админка ведущего** (`/admin`, вход по `QUESTAROUND_ADMIN_TOKEN`)
- Игры и сценарии: загрузка YAML (файлом или вставкой) с ошибками по строкам, версии, создание игры.
- Шапка игры: статус, код и ссылка, QR для афиши, «открыть как игрок», старт/завершение, сообщение всем.
- **Команды**: живая таблица — текущий уровень, сколько на нём (красным > 25 мин), секторы, подсказки,
  баллы, время со штрафами, активность (оранжевым — тишина > 10 мин); сортировка по прогрессу / «залипанию».
- **Карточка команды**: состав и контакт, история уровней с временем, ввод кода за команду,
  «засчитать уровень», подсказка без штрафа, ± время и баллы (с обязательной причиной), остановка,
  старт вручную, переименование, снятие до старта.
- **Регистрация**: открыть/закрыть, лимит команд, добавить команду вручную (ссылка-приглашение).
- **Модерация**: карточки с фото, принять/отклонить с комментарием, клавиши A / R.
- **Таблица**: живая, переключатель видимости для игроков (по сценарию / показать / скрыть).
- **Журнал**: все события по порядку с фильтром по команде — для спорных ситуаций.
- Всё обновляется по SSE; ввод в формах не сбрасывается при обновлениях.
